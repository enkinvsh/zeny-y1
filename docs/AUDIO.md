# Аудиодвижок zeny (Zeny Audio Engine)

Весь звуковой тракт плеера: декодер Opus, DSP, вывод. Реализация: `android/app/src/main/java/com/themoon/y1/managers/ZenyAudioProcessor.java` (эталон на Java) и `android/app/src/main/cpp/zenydsp.c` (то же самое на C).

## Что было не так в стоковом тракте

Снято с устройства (`dumpsys media.audio_flinger`, `dumpsys media.audio_policy`) и из кода приложения:

1. Выход AudioFlinger на Y1 умеет только 44100 Гц, а Opus декодируется в 48000 Гц. Android 4.2 переводил частоту целочисленным линейным ресемплером 160:147.
2. Приложение безусловно включало эффекты MediaTek (Equalizer, BassBoost, Virtualizer) даже со значениями «выкл»: поток шёл через 16-битный EffectChain.
3. Выравнивание громкости (Sound Check) на Android 4.2 не работало: код проверял `SDK_INT >= 19` (LoudnessEnhancer), на Y1 `SDK_INT = 17`. Декодер libopus отдавал 16 бит и срезал межсемпловые пики выше 0 dBFS внутри себя.
4. Программные процессоры `Y1EqAudioProcessor` и `Y1CrossfeedAudioProcessor` (теперь удалены) конвертировали short↔float на каждой стадии с жёстким клиппингом, без запаса по уровню и без дизеринга.

## Конвейер

Декодер libopus переведён в float (`opus_decode_float`), дальше всё считается в 32-битном float, и только на выходе квантуется в 16 бит. Порядок стадий: статическое усиление / AGC / Sound Check → Air → Сцена → ресемплер → мягкий клип → дизеринг. Эффекты MediaTek (Equalizer, BassBoost, Virtualizer) приложением больше не создаются: они работали в AudioFlinger после нашего 16-битного дизеринга и обрабатывали звук повторно. 10-полосного эквалайзера, пресетов и профилей наушников в плеере нет. Файлы FLAC идут через старый `MediaPlayer` мимо этой цепочки (Air и Сцена на них не действуют).

| Стадия | Что делает |
|---|---|
| Входное усиление | Запас -1.2 дБ под межсемпловые пики; один и тот же для всех шагов Air (полка уровень не срезает: на громких местах пики заходят в колено мягкого клипа, для плеера это допустимо). Sound Check: точное усиление из тега `R128_TRACK_GAIN` / `REPLAYGAIN_TRACK_GAIN` (диапазон -9.5…+4 дБ), для файлов без тега медленный гейтированный нормализатор (постоянные времени 3 с вверх, 6 с вниз). |
| Air (опция, по умолчанию выкл.) | Один фильтр первого порядка, высокая полка: шаги выкл / +6 / +9 / +12 / +15 / +18 дБ на плато выше примерно 20 кГц. Геометрическая середина 8 кГц: нуль на fm/√K, полюс на fm·√K, усиление на постоянной составляющей ровно 1. Басы, середина и резонансы не затрагиваются, нелинейности нет. Нуль ставится по matched-Z, полюс подбирается так, чтобы цифровая АЧХ совпала с аналоговой на 0.8 от Найквиста (прямое билинейное преобразование на 44.1 кГц ошибается до 6.9 дБ на 20 кГц). На +18 дБ и 44.1 кГц нужный полюс уходит левее нуля (отрицательный, но устойчивый): с полюсом в нуле усиление на 0.8 от Найквиста недобирает 0.3 дБ. |
| Сцена (опция, по умолчанию выкл.) | Комплементарный кроссфид, шаги 1/2/3 = подача 3 / 4.5 / 6 дБ при 700 Гц. Формула по каналам: `out_L = in_L − G·LP(in_L) + G·LP(in_R)` (симметрично для R), `G = 1/(1+10^(feed/20))`, `LP` — однополюсный ФНЧ 700 Гц с единичным усилением на постоянной составляющей. На НЧ прямой путь `1−G`, перекрёстный `G`, сумма ровно 1: центр и моно не меняют уровень на любой частоте (проверено побитово); выше 700 Гц прямой путь 1, перекрёстный стремится к нулю, потерь на ВЧ нет. Отдельной линии задержки нет: групповая задержка самого ФНЧ (около 217 мкс) служит межуншной. Шаг 0 пропускает ступень целиком. |
| Ресемплер 48 → 44.1 кГц | Полифазный оконный sinc (окно Кайзера, beta 6, 48 отводов, 147 фаз). Плоско до 19 кГц, -0.5 дБ на 20 кГц, подавление зеркала выше 23 кГц 52-68 дБ. Для нестандартных частот запасной кубический Эрмит. |
| Выход | Мягкое насыщение выше -1.7 dBFS (монотонное, колено C1) и треугольный дизеринг TPDF перед округлением до 16 бит. |

По умолчанию работает прозрачный тракт (Air выкл., Сцена выкл.): по измерениям `tools/audio-lab` отклонение АЧХ ±0.003 дБ, дизер на пределе 16 бит. Меню: Настройки → Звук → «Воздух» (Air), параметр `air_step` 0..5 (выкл, +6, +9, +12, +15, +18 дБ); «Сцена», параметр `crossfeed_step` 0..3 (имя ключа сохранено от прежнего кроссфида); там же строка Sound Check (`sound_check_enabled`) после «Сцены» и перед лимитом громкости. Однократная миграция `air_v2` пересчитывает сохранённый `air_step` из прежнего ряда 3/6/9/12 дБ в новый с тем же уровнем в дБ. При первом запуске включается Sound Check; однократная миграция `air_v1` удаляет устаревшие флаги `zeny_natural_enabled` и `pure_default_v1` (профиль Zeny Natural убран), шаг Сцены и Sound Check не трогает. Однократная миграция `cleanup_v1` удаляет настройки удалённых функций: `software_eq_enabled`, `eq_*` (пресеты, профили и уровни полос), `custom_eq_list`, `bass_boost_step`, `virtualizer_step` и устаревший `sound` (если звук колеса был выключен старым флагом, он переносится в `wheel_sound`). Файлы профилей эквалайзера на карте памяти не удаляются, приложение их просто не читает. Однократная миграция `cleanup_v2` удаляет ключи `album_tilt_enabled`, `video_stretch_fill` и файл настроек `Y1_LASTFM` (наклон обложки, растяжение видео и Last.fm убраны). «Сбросить настройки» возвращает Air и Сцену в «выкл.», Sound Check в «вкл.», лимит громкости, скорость и звук колеса в значения по умолчанию (а также перемешивание, вибрацию, пользовательский фон, скрытие и порядок пунктов меню, виджеты темы); флаги `air_v1`, `air_v2`, `cleanup_v1`, `cleanup_v2`, `pure_default_v1` остаются, чтобы миграции не запускались повторно.

## Нативное ядро

Тот же цикл на Java на Dalvik (Cortex-A7 1 ГГц, JIT нет) занимал до 70% одного ядра при воспроизведении, процессор держал полную частоту весь трек. Поэтому горячий цикл вынесен в `libzenydsp.so`.

Ограничения, которые определяют устройство файла:

* Плеер на Android 4.2 (API 17), а NDK собирает под API 21+. Поэтому в `zenydsp.c` нет ни одного вызова libc/libm (даже `memset`, целочисленного деления и `sqrtf`); `scripts/build-native.sh` падает, если `nm -u` показывает хоть один внешний символ.
* Java остаётся эталоном и запасным путём: если `.so` не загрузилась (эмулятор на другой архитектуре, файл не лёг в `/system/lib`), `ZenyAudioProcessor` считает на Java.
* Библиотека кладётся в `/system/lib` вместе с остальными JNI-библиотеками (`scripts/deploy-system.sh` делает это для всех `lib/armeabi-v7a/*.so` из APK).

Замер на реальном Y1 (`tools/dsp-test/run.sh device`, 10 с стерео 48 кГц, доля одного ядра):

| Режим | Java | Нативное |
|---|---|---|
| 44.1 кГц без ресемплера, Pure | 18.5% | 1.0% |
| 48 кГц sinc, Pure | 32.8% | 3.3% |
| 48 кГц sinc + прежний Natural (замер до замены на Air) | 39-50% | 5.3% |
| + AGC | 52% | 5.7% |
| + прежний EQ 10 полос (удалён) | 68% | 9.1% |

При реальном воспроизведении поток `ExoPlayer:Playback` в `top -t` показывает 5% против 30% на Java-сборке, суммарная загрузка системы около 11% против около 37%. Выигрыш по времени работы от батареи не измерялся.

## Теги громкости

Приложение читает тег `R128_TRACK_GAIN` (Q7.8 относительно -23 LUFS) или `REPLAYGAIN_TRACK_GAIN`. Первый можно записать без перекодирования: громкость измеряется по EBU R128 (`ffmpeg` с фильтром `ebur128`), результат пишется в Vorbis-комментарий Ogg Opus.

## Проверка

`tools/dsp-test/run.sh` собирает нативное ядро для Mac и гоняет настоящий класс на JVM:

* `Harness`: 16 групп (АЧХ ресемплера, клиппер, жёсткие входы, независимость от размера чанка, АЧХ Air против прототипа, бас при Air, шаг 0 = Pure, Sound Check, AGC, форматы 8/16/24/32/float, моно, flush при перемотке, другие входные частоты, прозрачность Pure, THD+N при Air, «Сцена»: моно побитово равно шагу 0, прямой и перекрёстный путь против формулы, линейность и THD+N, межуншная задержка), запускается для Java и для нативного ядра.
* `Parity`: 24 конфигурации (в том числе Сцена 1/3 вместе с Air 2 на 44.1 и 48 кГц), нативное ядро против Java на одном входе. Расхождение не больше 1 младшего бита. Тот же `Parity` прогнан и на самом Y1 (ARM-сборка против Java на Dalvik): результат совпал.

## Что не проверено

* Слуховая оценка: Air проверен измерениями (АЧХ, THD, клип), не на слух в слепом сравнении.
* Реальный выигрыш по батарее.
* После удаления эффектов MediaTek на устройстве не проверено, что цепочка AudioFlinger для сессии действительно пуста (`dumpsys media.audio_flinger`).
